## New capabilities

### Agent delegation
Agents in an orchestrated run can now hand a sub-prompt to another agent on the team and receive its final output as a tool result. Opt-in via `registerBuiltInTools(registry, { includeDelegateTool: true })`. Five guards: self-delegation, unknown agent, cycle detection, configurable depth cap (`maxDelegationDepth`, default 3), and pool deadlock. Delegated runs' token usage rolls into the parent's `maxTokenBudget` so sub-agents cannot silently bypass it. ([#123](https://github.com/open-multi-agent/open-multi-agent/issues/123) by [@JackChen-me](https://github.com/JackChen-me))

### `runTeam` DAG dashboard CLI
`oma runTeam ... --dashboard` writes a static HTML view of the resolved task graph after a run, including dependencies and per-task status. ([#122](https://github.com/open-multi-agent/open-multi-agent/issues/122) by [@ibrahimkzmv](https://github.com/ibrahimkzmv), follow-up docs in [#141](https://github.com/open-multi-agent/open-multi-agent/issues/141) by [@JackChen-me](https://github.com/JackChen-me))

### `outputSchema` enforcement and `defineTool` passthrough
The previously advisory `outputSchema` on `AgentConfig` is now enforced: results are parsed and validated, with one retry on validation failure. `defineTool` schemas pass through to the LLM provider. ([#149](https://github.com/open-multi-agent/open-multi-agent/issues/149) by [@Xin-Mai](https://github.com/Xin-Mai))

### Pluggable shared memory
`TeamConfig.sharedMemoryStore` accepts any `MemoryStore` implementation (Redis, SQLite, your own). `sharedMemory: true` keeps the existing in-process default. ([#157](https://github.com/open-multi-agent/open-multi-agent/issues/157) by [@JackChen-me](https://github.com/JackChen-me))

### Advanced LLM sampling
`top_p`, `top_k`, `repetition_penalty`, `min_p`, and `extraBody` are now first-class on agent and coordinator configs. Payload spread order is fixed so `extraBody` overrides sampling parameters but never transport. ([#163](https://github.com/open-multi-agent/open-multi-agent/issues/163) by [@apollo-mg](https://github.com/apollo-mg))

### `parallelToolCalls` exposed for OpenAI
Was previously hardcoded; now configurable per agent. ([#173](https://github.com/open-multi-agent/open-multi-agent/issues/173) by [@JackChen-me](https://github.com/JackChen-me))

### Two new providers
- **Azure OpenAI** adapter, closing the long-standing [#24](https://github.com/open-multi-agent/open-multi-agent/issues/24). ([#143](https://github.com/open-multi-agent/open-multi-agent/issues/143) by [@Klarline](https://github.com/Klarline))
- **Qiniu** provider for users on Chinese infrastructure. ([#154](https://github.com/open-multi-agent/open-multi-agent/issues/154) by [@JackChiang233](https://github.com/JackChiang233), follow-up README/CLI docs in [#165](https://github.com/open-multi-agent/open-multi-agent/issues/165) by [@JackChen-me](https://github.com/JackChen-me))

## Fixes

- **Context compaction persistence and turn dropping.** `compact` strategy was losing turns and not persisting compressed history. ([#161](https://github.com/open-multi-agent/open-multi-agent/issues/161) by [@apollo-mg](https://github.com/apollo-mg))
- **OpenAI mixed-content message ordering.** Tool messages must precede user messages in mixed content; previously emitted in the wrong order. ([#178](https://github.com/open-multi-agent/open-multi-agent/issues/178) by [@voidborne-d](https://github.com/voidborne-d))
- **Provider type widening on configs.** `AgentConfig`, `CoordinatorConfig`, and `OrchestratorConfig` were not using the full `SupportedProvider` union. ([#158](https://github.com/open-multi-agent/open-multi-agent/issues/158) by [@JackChen-me](https://github.com/JackChen-me))

## Behavior changes

`#163` removed two implicit defaults that some users may have relied on:

- `parallel_tool_calls: false` is no longer forced. If you need the old behavior, set `parallelToolCalls: false` explicitly (now exposed via [#173](https://github.com/open-multi-agent/open-multi-agent/issues/173)).
- The default `frequency_penalty` override has been removed.

These are behavior changes, not API breaks, but worth checking if you depended on the old defaults.

The same PR also moved the local `<think>` tag parsing out of the agent layer into `tool/text-tool-extractor.ts`. This is internal cleanup with no user-visible impact.
